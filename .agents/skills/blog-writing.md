# Skill: Technical Blog Writing (Medium-Style)

This skill governs the structure, tone, code inclusion, and asset handling for top-tier technical articles.

## Article Structure

### 1. Title & Subtitle (H1 & Subtitle)
* **Title**: Action-oriented, highlighting the value or outcome. (e.g., *How to Build a Custom YouTube Transcript MCP Server with Docker*)
* **Subtitle**: A one-sentence summary of the tech stack and the goal.

### 2. The Hook / Introduction (3-4 paragraphs)
* Identify a clear developer pain point or current trend.
* Explain what the reader will build or learn by the end.
* Set clear expectations: Prerequisites and time required.

### 3. Architecture / High-Level Design (H2)
* Use text-based ASCII flowcharts or clean markdown tables to show components, data flows, and interactions.
* Explain the *why* behind design choices.

### 4. Step-by-Step Implementation (H2 & H3s)
* Introduce files and directories one at a time.
* **Code Rules**:
  * Always specify the filename/path as a comment on the first line.
  * Keep code modular, standard-compliant, and self-documenting.
  * Explain key lines or logic immediately below the code block.

### 5. Verification & Testing (H2)
* Show command line commands to run, build, or test.
* Describe expected outputs so the reader can verify their setup works.

### 6. Conclusion & Call-to-Action (H2)
* Summarize what was accomplished.
* Suggest next steps or extensions (e.g., adding features, optimizing).
* End with a friendly, open-ended question to encourage comments.

---

## Technical Tone & Readability Guidelines
* **Tone**: Professional, encouraging, and authoritatively clear. Use "we" to build a collaborative learning feel (e.g., "Now we will configure the routes...").
* **Formatting**: Keep paragraphs short (maximum 3-4 sentences) to keep readers engaged on mobile and desktop interfaces.
* **Key Terms**: Bold key technical terms when first introduced.
